## Build write-up

I built a focused portfolio rather than a generic project gallery. The main decision was to keep four projects that support one direction: data engineering, analytics engineering, cloud, and applied AI.

I used a Next.js and TypeScript source project while developing, then kept a static HTML version in the portfolio repository for GitHub Pages. This makes the published files easy to inspect. The styling uses a dark navy base with cobalt and violet accents, large headings, and a data and AI hero visual.

AI helped with the first layout drafts, the responsive CSS, content structure, and implementation details. I reviewed the output, changed the visual direction several times, corrected the project selection, increased small text sizes, added the Portuguese page, and removed claims that did not match the real repository count.

The hardest break was not a runtime error. It was a credibility problem: the first version showed eight projects even though the profile had sixteen repositories, and too many cards weakened the story. I fixed it by showing sixteen public repositories as the overall count and four selected projects as the evidence.

The next build step is a case-study page for LH Nautical Lighthouse with the data model, quality checks, and architecture explained in more depth.

## Build-in-public story

I started with a portfolio that was technically live but not yet clear. The useful win was turning it into a focused page with real links, a Portuguese route, readable type, and a small project filter that helps a recruiter scan the work.

The limitation is that the site is still hosted on a GitHub Pages subdomain. It also does not have analytics, a custom domain, or a server-backed contact form yet. I am keeping those limitations visible instead of presenting the portfolio as finished infrastructure.
