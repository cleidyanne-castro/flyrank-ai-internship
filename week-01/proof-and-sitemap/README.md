# Week 1: Decide What You're Proving

## Proof statement

I build reliable data and AI systems from messy business data, and I am proving that to a hiring manager on a data engineering or applied AI team. I want that person to open a project repository and contact me for a conversation.

## Why this needs a portfolio

A CV can list Python, SQL, cloud, and AI experience. It cannot show how I choose a data approach, how I explain trade-offs, or whether the linked work is coherent and reachable. A portfolio gives the reviewer a place to test that proof.

## Sitemap

The portfolio keeps the path short:

- Home: the claim, selected work, and the main contact action.
- Work: four selected repositories with a clear data and AI direction.
- About: the stack, background, and working context.
- Contact: email, LinkedIn, GitHub, and résumé.
- Portuguese route: the same core path for Brazilian recruiters.

## Toolkit

- Main build partner: ChatGPT
- Source and deployment: GitHub and GitHub Pages
- Development stack: Next.js, TypeScript, HTML, CSS
- Public output: the portfolio URL and the source repository

## Sitemap pressure test

The first sitemap idea treated every repository as equally important. That made the portfolio behave like a list instead of a proof. The change was to keep sixteen repositories visible as the overall profile count but show only four selected projects in the main work section. That makes the path from claim to evidence shorter.
